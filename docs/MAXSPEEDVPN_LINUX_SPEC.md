# MaxSpeedVPN Linux — техническая спецификация v0.1

## Цель

Нативный клиент MaxSpeedVPN для Arch Linux на основе Linux/Avalonia-ветки v2rayN 7.24.8+. Клиент сохраняет совместимость с Xray и sing-box, но получает отдельный продуктовый интерфейс, безопасное управление TUN и готовые маршрутизационные режимы для пользователей из РФ.

## Лицензия и происхождение

- База: `2dust/v2rayN`, GPL-3.0.
- Производный код MaxSpeedVPN Linux распространяется под GPL-3.0.
- Название, логотип, официальный канал обновлений, домены и подпись релизов MaxSpeedVPN отделяются от GPL-кода согласно `TRADEMARKS.md`.
- В репозитории сохраняются исходные copyright notices и перечень third-party компонентов.

## Технологический стек

- .NET 10, C#.
- Avalonia 12 + Semi.Avalonia + ReactiveUI.
- Общая логика: существующий `ServiceLib`.
- Движки: Xray и sing-box; выбор движка остаётся совместимым с типом профиля.
- Хранилище профилей: существующий SQLite-слой v2rayN.
- Основная целевая платформа первой версии: Arch Linux x86_64.
- Артефакты первой версии: portable tar.zst и `PKGBUILD`; позже — AppImage/AUR при стабильном обновлении.

## Границы привилегий

GUI всегда работает от обычного пользователя. Привилегированные операции выполняет узкий helper через polkit:

- создание/удаление TUN;
- применение/откат policy routing;
- атомарное применение/удаление nftables kill switch;
- изменение DNS только через активный backend NetworkManager/systemd-resolved;
- очистка состояния после аварии.

Helper принимает только валидированную декларативную конфигурацию, не произвольную shell-команду. GUI хранит rollback snapshot. Прерванный запуск не должен оставлять DNS, маршруты или nftables в изменённом состоянии.

## Состояния сессии

`Disconnected -> Preparing -> Connecting -> Connected -> Disconnecting -> Disconnected`.

Ошибочные переходы завершаются в `Error` и обязательном cleanup. `Disconnect` идемпотентен во всех состояниях. Новый `Connect` отменяет или дожидается предыдущего teardown; два core-процесса для одной сессии запрещены.

## Главный экран

Desktop-first компоновка без перегруженного меню:

1. **Левая навигация:** Главная, Серверы, Подписки, Маршрутизация, Настройки.
2. **Верхняя статусная строка:** состояние, активный сервер, движок, TUN/System Proxy, выбранный РФ-пресет.
3. **Центральная карточка:** большая кнопка Подключить/Отключить, сервер, задержка, адрес выхода, время сессии, down/up.
4. **Быстрые переключатели:** TUN, kill switch, авто-подключение, региональный пресет.
5. **Журнал на главном экране:** закреплённая нижняя панель с уровнями, поиском, паузой, автопрокруткой, копированием и экспортом диагностического пакета. Секреты и UUID редактируются перед показом/экспортом.
6. **Диагностика:** отдельная компактная панель DNS, default route, TUN, core PID/версия, geo-data version, последние ошибки.

Минимальная ширина 800 px. При узком окне журнал сворачивается в drawer. Все действия доступны с клавиатуры; фокус видим; состояние не кодируется только цветом.

## Визуальная система

- Только тёмная тема в v0.1: фон `#0F172A`, поверхность `#10192E`, текст `#F8FAFC`, connected `#22C55E`, warning `#F59E0B`, error `#DC2626`.
- Основной шрифт — системный sans; моноширинный — системный monospace для журнала. Внешние web-font зависимости запрещены.
- Иконки SVG, без emoji.
- Прозрачность окна: 70–100%, по умолчанию 100%; эффект применяется к фону, а текст/controls сохраняют читабельность. Если compositor/Wayland не поддерживает blur/transparency, используется непрозрачный fallback.
- Движение 150–250 ms, отключается при reduced motion.

## Региональные пресеты РФ

Правила всегда компилируются в явный порядок: пользовательские исключения -> LAN/loopback -> служебные адреса TUN -> блокировка -> прямой доступ -> proxy -> финальный fallback.

### 1. РФ: совместимость (рекомендуется)

- LAN/loopback напрямую.
- Российские домены/IP — напрямую по поддерживаемым geo-наборам.
- Остальное — через proxy.
- DNS split-horizon: DIRECT-запросы через системный/выбранный российский resolver, PROXY-запросы через защищённый DNS внутри туннеля.
- При отсутствии валидных geo-данных режим не активируется молча: используется последняя проверенная версия либо подключение блокируется с понятной ошибкой.

### 2. РФ: максимум доступа

- Только LAN и пользовательский allow-direct идут напрямую.
- Остальной трафик и DNS — через proxy.
- Предпочтительный режим для публичного Wi-Fi и сетей с DNS-подменой.

### 3. РФ: минимум VPN

- По умолчанию DIRECT.
- Через proxy идут только подтверждённые пользовательские списки и поддерживаемые anti-filter/community rule sets.
- UI явно предупреждает, что полнота обхода зависит от актуальности источника.

### 4. Всё через VPN

- LAN — опционально напрямую.
- Всё остальное, включая DNS, через proxy.

### Опции поверх пресета

- Блокировка рекламы/трекеров отдельным переключателем.
- Пользовательские DIRECT/PROXY/BLOCK домены и CIDR всегда имеют приоритет и видны до применения.
- Банки, Госуслуги и другие чувствительные сервисы не захардкожены вручную: они следуют выбранному проверяемому rule set либо явным пользовательским исключениям.
- Источники geo/ruleset скачиваются во временный файл, проверяются по формату/размеру/контрольной сумме, затем заменяются атомарно. Есть дата, источник и откат к предыдущей версии.

## DNS

- Режимы: `Следовать пресету`, `Защищённый`, `Системный`, `Экспертный`.
- Защита от DNS leak проверяется после подключения.
- Если NetworkManager управляет resolved, изменения выполняются через NM, а не параллельной правкой `/etc/resolv.conf`.
- Отключение восстанавливает исходный DNS даже после ошибки core.

## Kill switch

- Выключен по умолчанию до первого успешного self-test.
- Режимы: только при подключении; постоянный до ручного отключения.
- Разрешены loopback, LAN по настройке, DHCP/NDP, endpoint текущего VPN-сервера и трафик TUN.
- Таблица nftables имеет уникальное имя MaxSpeedVPN и удаляется атомарно при штатном shutdown.
- Watchdog/helper очищает stale-state после падения GUI/core.

## Дополнительные функции удобства и надёжности

- Health-based auto-select с гистерезисом, чтобы не прыгать между серверами.
- Автоподключение по типу сети: доверенная домашняя сеть / неизвестный Wi-Fi / проводная сеть.
- Переподключение после suspend/resume и смены сети.
- Проверка IPv4, IPv6, DNS и captive portal до включения строгого kill switch.
- Импорт из буфера, QR-файла, URL и подписки; дедупликация без потери пользовательского имени.
- Резервное копирование настроек с исключением секретов по умолчанию.
- Диагностический ZIP: версии, красныеacted logs, сгенерированный config без ключей, `ip rule/route`, DNS и nftables snapshot.
- Уведомления только о важных переходах, ошибки доступны из tray.
- Безопасное обновление приложения, core и geo-data как отдельных компонентов с проверкой подписи/checksum и rollback.

## Вертикальные этапы реализации

1. Тестируемая state machine с idempotent teardown и bounded журналом.
2. Подключение существующего CoreManager к состояниям и redacted log stream.
3. Компилятор РФ-пресетов с unit snapshot tests для Xray/sing-box.
4. Polkit helper + TUN/DNS/nftables rollback tests в namespace/VM.
5. Новый Avalonia главный экран и прозрачность.
6. `PKGBUILD`, clean-chroot build, установка/удаление и API/UI smoke на Arch.

## Критерии выпуска

- Все ServiceLib.Tests проходят.
- Отдельные tests подтверждают переходы, disconnect races, redaction, порядок routing rules и откат привилегированного состояния.
- `dotnet publish linux-x64` проходит в чистом окружении.
- `makepkg --cleanbuild` проходит на Arch.
- Xray и sing-box проходят по два цикла connect/disconnect в system proxy и TUN режимах.
- После kill/crash отсутствуют stale core, TUN, nftables, routes и DNS override.
- DNS/IPv4/IPv6 leak checks соответствуют выбранному пресету.
- UI проверен в KDE Wayland и X11: dark theme, tray, keyboard, scaling 100/125/150%, opacity fallback.
- Установка и удаление пакета не затрагивают пользовательские данные без явного запроса.
